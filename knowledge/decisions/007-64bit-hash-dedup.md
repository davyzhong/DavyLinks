# ADR-007: 64 位哈希去重

**状态**: ✅ 已实施 (v2.0, 2026-06)

## 背景

v1.0 用 32 位 hash 作为文章指纹。按生日悖论，32 位空间（约 43 亿）在约 7 万篇文章时碰撞概率达 50%。

对 DavyLinks 当前规模（<1000 篇/天，90 天窗口 ≈ 9 万篇存留）——**已经逼近碰撞高发区**。一次哈希碰撞 = 一篇新文章被误判为已处理，静默丢失。

## 备选方案

| 方案 | 碰撞风险 | 代价 |
|------|----------|------|
| 32 位 hash（现状） | 7 万篇 50% | ❌ 已到危险区 |
| 直接存完整 URL | 零 | URL 长，作为 hash 使用时比较开销大 |
| MD5/SHA1 (128 位) | 趋零 | 引入 hashlib 依赖（其实标准库自带），字节长 |
| **64 位 hash** | 趋零 | 字符串长度翻倍（16 hex chars） |

## 决策

`hash_url()` 从 32 位扩展到 **64 位**（16 hex chars）。`tests/test_immutability.py` 中有专门测试验证返回值 < 2^64 且确定性。

## 后果

- ✅ 10 万篇碰撞概率从 69% 降到 0.000001%
- ✅ 仍是纯 Python `hash()` 派生，无新依赖
- ⚠️ 注意：Python 内置 `hash()` 对 str 有随机化（PYTHONHASHSEED），进程间不一致——但去重只依赖**单进程内**的一致性（同一运行中比对），且真正的持久层主键是完整 URL，hash 仅作辅助，无实际影响
- 碰撞概率对比表见 [evolution/v2.0-code-review.md](../evolution/v2.0-code-review.md)
